# Publication-artifact reproduction

## Command

```bash
python scripts/reproduce.py publication --jobs 1
```

## What is rebuilt from numerical sources

All five main figures and ten supplementary figures are regenerated by `scripts/build_publication_figures.py` from the CSV files in `figure_sources/`. The rebuild produces PNG and EPS outputs.

## What is preserved as a publication-layer reference

The exact locked submission PNG/EPS files and the styled Excel workbooks are retained under `publication_reference/`. The publication command re-materializes these files and verifies SHA-256 identity. This preserves exact typography/layout without implying that typography is a statistical computation.

## Reproducibility boundary

The model-development P0–P3 comparison and ten-model architecture-selection stage remains covered by retained machine-readable results and verification materials rather than end-to-end retraining of every candidate model from raw model-development inputs. Downstream target-domain analyses remain executable as described in `README.md`.

## Expected generated contents

- 15 rebuilt PNG + 15 EPS figures
- 15 locked PNG + 15 locked EPS submission figures
- 3 publication-source XLSX workbooks
- 2 caption text files
- artifact SHA-256 verification report

## Export robustness

The 15 data-driven figures are exported in isolated worker processes (up to four by default for the publication profile). This prevents Matplotlib backend/font state from accumulating across sequential EPS exports. Use `--jobs 1` for a fully serial diagnostic build.
